# 领域决策日志（ADR）

## 使用规则

每个真实决策至少写清：**语境 / 选项及技术后果 / 决定 / 理由 / 验证 / 推翻条件**。

- 决策一旦写下，推翻它需要新条目，而不是覆盖旧判断。
- `doc/DDD建模示例.md` 中的 `ADR-EX-001`、`ADR-EX-002` 是基于 DDD v0.2 已明确取舍的完整写法示例，**不代表下列待决项已被所有者关闭**。
- 长期候选不批量创建 ADR；只有实际操作迫使取舍出现时才记录。
- 技术配置坑写入 `doc/阶段技术指引.md`，领域模型取舍才写在这里。

## ADR-001 Timer 建模（待所有者确认）

- **语境**：前端需要持续显示活跃计时；DDD v0.2 以 ExecutionSegment 表达实际执行，活跃段的 `ended-at` 为空。现有代码另有“全局至多一个活跃计时”的技术约束。
- **选项**：
  - **A. 独立 Timer 实体**：可以单独表达设备、心跳或计时器生命周期，但当前会多出一份需要与 ExecutionSegment 对齐的状态。
  - **B. ExecutionSegment 的 `ended-at = NULL` 状态**：事实只有一份，暂停／恢复天然形成段边界；计时器生命周期细节不能直接塞入该模型。
- **决定**：＿＿＿＿＿＿（DDD v0.2 提案为 B，待所有者确认）
- **理由**：＿＿＿＿＿＿
- **验证**：刷新或重开后仍能由活跃段恢复计时；暂停／恢复不会创建新 TaskInstance；实际投入按段求和。
- **推翻条件**：出现独立计时设备、心跳或跨实例计时器生命周期，且无法由 ExecutionSegment 表达。

## ADR-002 删除实例时执行段与结果的归属（待决；当前不阻塞）

- **语境**：当前 DDD v0.2 最小操作集没有 `DeleteTaskInstance`。只有删除真实进入用例时才需要关闭本项。
- **选项**：
  - **A. 删除实例但保留历史记录**：需要可查询的历史快照、软删除或让执行段引用可空／归档实例；不能靠关闭外键保留无意义孤儿 ID。
  - **B. 级联删除执行段与结果**：存储简单，但会永久丢失投入与结果历史。
  - **C. 只允许归档，不允许物理删除**：最保护历史，但需要明确归档查询与排除口径；当前不能假装已经存在该命令。
- **决定**：＿＿＿＿＿＿
- **理由**：＿＿＿＿＿＿
- **验证**：删除或归档后，执行段、结果、模板归属、TaskSetMembership 和 TaskRelation 的引用完整性都有明确结果。
- **推翻条件**：法规、隐私或真实统计需求改变历史保留要求。

## ADR-003 Start 接口幂等性（待决）

- **语境**：同一 TaskInstance 重复 Start 可能由双击、重试或网络重发触发；若保留全局单活跃计时，还涉及当前活跃段属于哪个实例。
- **选项**：
  - **A. 重复 Start 一律 409**：客户端容易发现重复操作，但网络重试不友好。
  - **B. 同一实例已有活跃段时幂等返回 200**：重试安全；其他实例已有活跃段仍需按全局约束返回 409。
- **决定**：＿＿＿＿＿＿
- **理由**：＿＿＿＿＿＿（必须分别说明“同实例重复”和“其他实例冲突”）
- **验证**：双击、重试和并发 Start 后数据库仍至多一个活跃段，响应语义稳定。
- **推翻条件**：引入命令幂等键或改变全局活跃计时约束。

## ADR-004 进行中计时在前端的呈现（待决）

- **语境**：re-frame app-db 应是服务器事实与本地 UI 状态的投影，不应成为另一份执行事实。
- **选项**：
  - **A. app-db 缓存活跃段，本地时钟只负责显示**：交互顺畅；必须根据 `started-at` 派生显示时长，不能每秒递增并回写 `elapsed` 当事实。
  - **B. 每次从后端查询活跃投影**：一致性直接，但请求与加载状态更多，仍需本地时钟平滑显示。
- **决定**：＿＿＿＿＿＿
- **理由**：＿＿＿＿＿＿
- **验证**：刷新、后台标签页节流、断网重连和服务器重启后，显示时长与原始执行段一致。
- **推翻条件**：出现离线执行或多设备同时写入，需要更明确的同步协议。
