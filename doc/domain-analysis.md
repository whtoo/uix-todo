# 领域分析工作表

> 方法链：OOA 抽取（名词清单 + 用例走查）→ DDD 两道筛子 → Clojure 三个落点。
> 本表是 ADR 的上游：模型级决策先在此登记；涉及多方案取舍时，另立 ADR（见 doc/decisions.md）。

## 工作流

1. **OOA 抽取**：从需求叙述抽名词，求全不求准；再用用例走查补漏。
2. **筛子一 · 生命周期/不变量**：有自己的生命周期和不变量 → 实体候选；没有 → 值对象、投影，或淘汰。
3. **筛子二 · 一致性边界**：一起变、一起校验的归同一聚合；跨聚合不变量显式标注为事务级规则。
4. **Clojure 落位**：通过的模型落三个位置——registry 加条目（词汇表）、写面命名空间加函数族（行为）、DDL 加约束（L3）。

## 登记规则

- **否定决策必须留痕**：为什么 X 不是实体，要写清理由——否定决策比肯定决策更能防止后来者走回头路。
- **名词 ≠ 模型**：没有只能由自己维护的不变量，就不是写模型的成员。
- **上下文边界信号**：同一名词在不同语境下含义漂移（被消费的属性子集不同），是限界上下文切分的候选信号。
- **全流程门禁**：新模型必须走完「四栏登记 → 两道筛子 → 三个落点」，不许跳步直接写 schema。
