## REPL 交互开发工作流

### 三种入口

| 方式 | 命令/操作 | 适合 |
|---|---|---|
| 终端直接 | repo 根目录 `clj` | 零配置，落在 user ns |
| 编辑器 jack-in（推荐日常） | VS Code+Calva："Calva: Start a Project REPL and Connect (jack-in)"；Emacs+CIDER：`M-x cider-jack-in-clj` | 光标处 eval 单个表单/defn，主工作流 |
| 独立 nREPL | `clj -M:nrepl`（监听 :9000） | 已开着的编辑器直接 "Connect to a running REPL" |

注：`:nrepl` 起的会话不自动加载 user ns，首条 `(require 'user)` 或直接 require 目标 ns 即可；端口占用用 `lsof -nP -ti :9000` 清理（kill 查到的 PID 才是监听进程）。

### 交互循环（Stage 1 具体化）

1. REPL 里先 `(require '[loom.db :as db])` → 写 `datasource` → `(require 'loom.db :reload)` → `(def ds (db/datasource))` → `(db/ensure-schema! ds)`。
2. 之后每实现一个 defn：保存 → 对应 ns `:reload`（编辑器 eval 单表单则连 :reload 都省了）→ 跑下面 Stage 1 的"REPL 冒烟链"逐条验证。
3. 探索代码写在各 ns 尾部 `(comment ...)` 块（可执行笔记），行为冻结后升为正式 defn——user.clj 文件头纪律。
4. `defonce` 不随 :reload 更新（坑10）：重建 def 即可，别重启 REPL。
5. 行为冻结点：一条垂直切片在 REPL 全绿 → 立即 commit（AGENTS.md 完工协议，快照纪律）。

### 不重启的热替换（Stage 2 起）

开发期服务不要用 `clj -M -m app.main`（独立进程，改一行要重启）。在 REPL 内：

```clojure
(require '[app.main :as main])
(main/start!)        ; 或 (main/start! 3080)
;; 改 handler/app 后只 eval 该 def——run-server 持有 #'app Var，热替换立即生效
(main/stop!)         ; 换端口或重启前先停
```

`defonce server` + `#'app` 间接层就是为这个循环设计的（app.main ns docstring 的验收点）。

## Stage 1：数据层（当前）

### 配置现状

依赖已解锁并验证（next.jdbc / honey.sql require 通过、org.sqlite.JDBC 可加载）。
你要写的：`loom.db` 的 `datasource`/`ensure-schema!`/`snake-kebab-opts`，`loom.task`/`loom.time` 六个函数，`user.clj` 的 `:db/reset`/`:db/seed`，ADR①② 注释。

### 逐坑清单

**坑1：next.jdbc 出口 key 是 `CREATED_AT` 风格**
症状：`(:created-at row)` 拿不到值，`(:CREATED_AT row)` 才有。
解法：出口统一 `(jdbc/execute-one! db sql {:builder-fn rs/as-unqualified-kebab-maps})`，
`(require '[next.jdbc.result-set :as rs])`。builder-fn 是 execute-*/execute! 的 opts，**不是** datasource 的——不要配错层。

**坑2：领域关键字直接进 SQL**
症状：honeysql 里 `:task/id` 会被格式化成**表限定列** `task.id`，报 no such column。
解法：领域 map 永远先过映射函数（`task->row`/`entry->row`）变成裸列名 map 再进 honeysql——这就是 ACL 边界的意义。条件值不需要手工参数化：honeysql 2 对 where/values 里的值自动生成 `?` 占位。

**坑3：`with-transaction` 体返回 nil = 回滚**
症状：插入明明执行了，事务结束数据没了。
原因：next.jdbc 约定——体返回 `nil`/`false` 即 ROLLBACK。
解法：`start-timer!` 等事务体的**最后一个表达式必须返回真值**（比如返回创建的 entry map），不要顺手返回 nil。

**坑4：SQLite 没有 UUID / 布尔 / 日期类型**
解法：UUID 存 TEXT（`(str uuid)` / `(parse-uuid s)`，DDL 已是 TEXT）；时间一律 epoch millis 整数 `(System/currentTimeMillis)`，**不存 ISO 字符串**；布尔用 0/1。

**坑5：部分唯一索引与 NULL 语义**
SQLite 普通唯一索引里多个 NULL 互不冲突——所以"全局至多一个活跃计时"必须靠已有的
`uniq_active_timer ... WHERE end_ts IS NULL`（只索引 end 为空的行）。两条活跃计时 → 插入第二条抛 SQLITE_CONSTRAINT。
L2/L3 双保险：事务内先查 active（抛 `:time/conflict`），索引兜底；插入处可 catch SQLException 转译成 `:time/conflict`。

**坑6：SQLite 外键默认不启用**
`REFERENCES tasks(id)` 写在 DDL 里 ≠ 生效；不开 `PRAGMA foreign_keys = ON` 时删任务会静默留下孤儿条目。
这与 **ADR-002** 直接相关：选"保留条目"则现状即语义（但建议注释里写明是刻意依赖 FK 关闭）；选"级联删"则必须在 `delete-task!` 里事务内手动删两张表（现有 DDL 没有 ON DELETE CASCADE，别指望 DB 帮你）。

**坑7：`:memory:` + datasource = 每次连接都是空库**
症状：建了表，下一条语句报 no such table。
原因：`:memory:` 每个新连接一个全新库。
解法：测试/练习用临时文件 `(str (System/getproperty "java.io.tmpdir") "/taskloom-test-" (System/nanoTime) ".db")`，或共享缓存 `file::memory:?cache=shared`（配单 datasource）。REPL 正式练习直接用 `data/taskloom.db`。

**坑8：database is locked**
SQLite 单写者。REPL 与别的进程（测试、第二个 REPL）同写一个文件会撞锁。
解法：保持单连接纪律（datasource 惰性、用完不攒连接）；可选 WAL：启动时
`(jdbc/execute-one! ds ["PRAGMA journal_mode=WAL"])`。练习阶段不必上连接池。

**坑9：`mi/instrument!` 对普通 `defn` 是 no-op**
任务卡第 7 条的装配只对带 schema 的函数生效（`malli.experimental/defn` 即 `:>defn`，或 :fn schema 元数据）。
现桩位是普通 defn——要么实现时直接用 `:>defn` 写 schema，要么接受 instrument 阶段为空操作并在注释里说明。

**坑10：REPL 重载纪律**
改了 `(require 'loom.task :reload)`；`defonce` 的 datasource 不会跟着新——重置命名空间用
`(require 'loom.db :reload)` 后重建 datasource。探索代码长在 `user.clj`，冻结后才进正式 ns（文件头纪律）。

### 就绪后的 REPL 冒烟链（自测用）

```clojure
(require '[loom.db :as db] '[loom.task :as task] '[loom.time :as time])
(def ds (db/datasource))
(db/ensure-schema! ds)
(def t (task/create-task! ds {:task/id (random-uuid) :task/title "第一个任务"}))
(task/get-task ds (:task/id t))          ; 字段无损读回
(task/list-tasks ds nil)                 ; status/tag 过滤
(time/start-timer! ds (:task/id t))
(time/active-timer ds)                   ; end-ts 为空
(time/start-timer! ds (:task/id t))      ; 应抛 :time/conflict
(time/stop-timer! ds)                    ; end 落当前时间
(time/list-entries ds {:task-id (:task/id t)})
(task/delete-task! ds (:task/id t))      ; 行为 = 你在 ADR-002 的决定
;; 重启 REPL 后重复 get-task/list-entries → 数据仍在（持久化验收）
```

## Stage 2：REST API（预告，任务卡 = 学习路径阶段4）

- 依赖门：`metosin/reitit-malli`（与 reitit 同版本 0.11.0）。
- 坑：coercion 失败默认是 reitit 异常封装，前端/测试无法消费 → 必须 exception handler 统一格式化（`malli.error/humanize`）。
- 坑：`:time/conflict` 这类领域异常要显式映射 409；校验失败 400——语义分界先想清楚再写 handler。
- 坑：muuntaja 解码要求请求带 `Content-Type: application/json`，curl 测试别忘了 `-H`。
- 路由只做编排：handler 薄，业务进 `loom.task`/`loom.time`，别把 SQL/事务写进 handler。

## Stage 3：验证与打包（预告，任务卡 = 学习路径阶段6）

- 依赖门：`io.github.clojure/tools.build` + 根目录 `build.clj`；`app.main` 已有 `:gen-class`，uberjar 入口现成。
- 时机：4 个 `:pending` 测试在本阶段解锁；属性测试生成器从 `loom.schema` registry 派生（`malli.generator`），非法输入从源头排除。
